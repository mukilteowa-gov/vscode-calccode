# Developing and releasing Calc Code

Maintainer notes. Not shipped in the .vsix.

## Layout

```
lib/lint-core.ts      the checker, a pure function: text in, issues out
lib/rules.json        editor width, comment markers, paste-corruption tokens
lib/library.json      cluster and attribute library (generated, see below)
reference.md          the library as a document (generated)
src/extension.ts      VS Code glue: completion, hover, diagnostics, quick fixes
src/format.ts         the re-indenter
syntaxes/ snippets/   grammar and snippets
test/                 plain assertion tests
examples/             lint-demo.calc, one block per checker rule
```

Everything the extension needs is in this folder. Nothing in it imports from outside.

## Build

```bash
bun install
bun run test         # formatter and checker tests
bun run compile      # esbuild bundle to out/extension.js
bun run package      # test, compile, write calc-<version>.vsix
```

Press F5 in VS Code for the Extension Development Host. bun is the task runner and
esbuild the bundler; npm is not needed. `vsce` runs under the bun runtime because it
fails on Node 18.

## Where the library comes from

`lib/library.json` and `reference.md` are generated by a script that lives with its
source data in the Mukilteo orca-stack repository
(`packages/fe-bridge/scripts/fe-calc-library-build.ts`). Inputs:

1. the Finance Enterprise PYUPCL cluster catalog dump (clusters, attributes, types,
   array sizes, help text)
2. the Cluster_attribute_PY Reference workbook (screen masks, titles, a few extra
   attributes)
3. the documented LOAD forms and a short list of common attribute values

Nothing site-specific ships, and no vendor documentation text ships: the catalog's help
prose and long cluster notes are dropped at generation time. What remains is names,
labels of 24 characters or less, types, lengths, array sizes and screen masks, which are
the identifiers any calc must use. The generator also runs a census of that site's live calcs
purely as a check that no live token falls outside the library; the census does not
change the output. To regenerate, run the script from that repository; it writes into
this folder.

For a standalone checkout without the generator, `lib/library.json` is plain JSON and
can be edited by hand. Users add site clusters through the
`calccode.library.extraClusters` setting instead.

## Splitting into its own repository

```bash
git subtree split -P tools/vscode-calccode -b vscode-calc-split
git push <new-remote> vscode-calc-split:main
```

Then update `repository` in package.json and point the generator's output path at the
new checkout.

## Release checklist

- [ ] `bun run test` and `bun run package` are clean
- [ ] `examples/lint-demo.calc` shows every rule it claims to
- [ ] version bumped in package.json (VS Code refuses to install an equal version)
- [ ] CHANGELOG.md has an entry
- [ ] no site-specific names, paths or data in README.md, snippets, library.json,
      reference.md or messages (`grep -ri "mukilteo\|orca" .` outside this file)
- [ ] no special characters in messages or docs (`grep -n "[^ -~]" lib src README.md`)
- [ ] LICENSE is MIT (code); the library ships identifiers only, no vendor prose
- [ ] name decided: `calccode` is the language id, file extension, extension id and
      display name; renaming after release breaks users' settings and file associations,
      so settle it before 1.0.0
- [ ] `publisher` in package.json matches the account that will publish

## Review guide

Give a reviewer the .vsix, the calc files they normally work with, and this list.

1. Install, reload, open a real calc. Coloring, folding, the 58-column ruler.
2. Hover three things: a `CLUSTER.ATTR`, a bare cluster name, a keyword.
3. Type `NVAR0 := ` and confirm clusters and registers are offered; type `PBSX.` and
   confirm the attribute list; type `LOAD(` and confirm the forms.
4. Open `examples/lint-demo.calc` and confirm each numbered block gets a squiggle.
5. Break a real calc on purpose: drop an ENDIF, misspell a cluster, push a line past
   58. Confirm the message says what is wrong in one plain sentence.
6. Run Format Document on a real calc and diff the result: only indentation changed,
   no comment touched.
7. Look for anything false or presumptuous: a message that claims to know what a
   site's engine does, a name in the library that does not exist on their system, a
   value suggestion that is wrong for them.
8. Report: what was wrong, what was noise, what was missing.
